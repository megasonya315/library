
# Text Index Library

Библиотека для высокопроизводительной индексации текстовых файлов по словам. Предоставляет API для встраивания в Java-приложения и консольный клиент (CLI) для интерактивного поиска.

## Архитектура и принятые решения

Согласно требованиям задания, реализация содержит собственные архитектурные решения для обеспечения надежности, производительности и расширяемости.

### 1. Дизайн системы
*   **Пакетная структура:** Разделение на `api` (контракты), `core` (логика), `watcher` (мониторинг ФС) и `cli` (интерфейс). Это соответствует принципу разделения ответственности (SRP) и позволяет заменять реализации без изменения контрактов.
*   **Неизменяемая конфигурация:** Настройки передаются через `IndexConfig.Builder`. Это гарантирует, что настройки индекса не будут изменены случайно в процессе работы.
*   **Factory Pattern:** Использование `TextIndexFactory` скрывает сложность инициализации пулов потоков и `WatchService` от потребителя библиотеки.

### 2. Concurrency
*   **ReadWriteLock:** Для защиты индекса используется `ReentrantReadWriteLock` вместо `synchronized`. Это позволяет выполнять множество операций чтения (`search`) одновременно, блокируя запись только при обновлении индекса. Это значительно повышает пропускную способность при сценариях "много чтений, редкие записи".
*   **ExecutorService:** Индексация файлов вынесена в фоновые потоки, чтобы не блокировать вызывающий поток при добавлении больших каталогов.
*   **Atomic Operations:** Использование `ConcurrentHashMap` и `AtomicInteger` для счетчиков метрик без лишних блокировок.

### 3. Работа с файловой системой (File Watcher)
*   **Рекурсия:** Стандартный `WatchService` не поддерживает рекурсивную регистрацию каталогов "из коробки". Реализована ручная рекурсивная регистрация: при добавлении каталога или создании новой папки в ней система автоматически обходит дерево и регистрирует все поддиректории.
*   **Debounce:** Введен механизм debounce (задержки) для событий модификации файлов. Это предотвращает многократную переиндексацию одного файла, когда редакторы кода или Git генерируют серию быстрых событий (создание временных файлов, сохранение и т.д.).
*   **Overflow Handling:** При переполнении очереди событий ОС (`OVERFLOW`), система выполняет полную переиндексацию затронутого каталога.

### 4. Токенизация
*   **Unicode Support:** Регулярное выражение `\p{L}[\p{L}\p{N}_]*` позволяет корректно обрабатывать текст на любых языках (включая кириллицу, эмодзи и т.д.), отсекая только пунктуацию и спецсимволы.
*   **Extensibility:** Интерфейс `TextTokenizer` позволяет заменить стандартный парсер на любой другой (например, основанный на `BreakIterator` или NLP-библиотеках) без переписывания ядра.

##  Настройка окружения и сборка

### Требования
*   JDK 17 или новее
*   Apache Maven 3.6+

### Сборка
```bash
# Клонирование репозитория
git clone <repository-url>
cd text-index

# Очистка, компиляция и сборка
mvn clean package
```
Готовый исполняемый JAR-файл будет находиться в директории `target/`.

## Запуск приложения (CLI)

### Вариант 1: Через Maven
```bash
mvn exec:java
```

### Вариант 2: Через JAR
```bash
java -jar target/text-index-1.0.0-SNAPSHOT.jar
```

### Пример использования CLI
```text
> add C:\Users\Docs
Добавлено: C:\Users\Docs
> search java
Найдено 3 файлов:
  - C:\Users\Docs\guide.txt
  - C:\Users\Docs\notes.md
> status
Проиндексированные файлы: 15
Уникальные слова: 450
> quit
```

**Настройка кодировки:**
По умолчанию файлы читаются в `UTF-8`. Если ваши файлы сохранены в другой кодировке (например, `windows-1251`), используйте флаг `--charset`:
```bash
mvn exec:java -Dexec.args="--charset windows-1251"
```

## Использование библиотеки в коде

Пример интеграции в Java-приложение:

```java
import com.library.TextIndexFactory;
import com.library.api.IndexConfig;
import com.library.api.TextIndex;
import java.nio.file.Paths;

public class Example {
    public static void main(String[] args) {
        IndexConfig config = IndexConfig.builder()
                .maxThreads(4) // Настройка пула потоков
                .debounceMs(200) // Задержка перед реакцией на изменения
                .build();

        // try-with-resources гарантирует корректное завершение потоков
        try (TextIndex index = TextIndexFactory.createTextIndex(config)) {
            index.addPath(Paths.get("src/main/resources/docs"));
            
            // Мгновенный поиск
            index.search("concurrency").forEach(System.out::println);
        }
    }
}
```

## Тестирование

Проект покрыт тремя уровнями тестов, гарантирующих корректность работы в многопоточной среде.

```bash
# Запуск всех тестов
mvn test

# Запуск конкретного теста
mvn test -Dtest=WatcherIntegrationTest
```

| Тип теста | Описание |
| :--- | :--- |
| **Unit** (`core`) | Проверка токенизатора (Unicode, пунктуация), логика добавления/удаления из мапы, обработка бинарных файлов. |
| **Integration** (`watcher`) | E2E тесты: создание файла на диске → автоматическое появление в поиске, удаление → исчезновение. |
| **Concurrency** | Нагрузочное тестирование: одновременное чтение и запись из множества потоков для проверки отсутствия `Deadlock` и потери данных. |

## Известные ограничения
*   Индекс хранится в оперативной памяти.
*   Глубина рекурсии для `WatchService` может ограничиваться настройками ОС (лимиты `inotify` на Linux).
